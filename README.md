### Integration Gateway: MaxPatrol SIEM ➔ TrueConf Notifier

Асинхронный Python-бот для автоматического сбора инцидентов информационной безопасности из **MaxPatrol (SIEM)** и их оперативной публикации в корпоративный мессенджер **TrueConf Server**. 

Бот агрегирует информацию об инциденте и автоматически подтягивает связанные события ИБ, вызвавшие сработку, формируя единую структурированную карточку оповещения. 

### ✨ Ключевые возможности

* **Сбор связанных событий:** Бот не просто присылает сухую карточку инцидента, а запрашивает через API SIEM детальные события (логи), приведшие к генерации инцидента, и выводит первые N штук прямо в чат.
* **Гарантия доставки (Отказоустойчивость):** Если сервер TrueConf временно недоступен (сетевой сбой, плановые работы), бот **не сдвигает временную метку** обработки. После восстановления связи он автоматически выгребет из SIEM и дошлет в чат *все* пропущенные инциденты по порядку.
* **Умный трекинг времени:** Метка последнего обработанного инцидента сохраняется в файл с точностью до миллисекунд (+1 мс к последнему инциденту), исключая дублирование или пропуски сообщений.
* **Асинхронный движок:** Работа с TrueConf реализована через долгоживущее WebSocket-соединение в асинхронном Event Loop (asyncio, websockets), что минимизирует нагрузку и обеспечивает мгновенную отправку.
* **Красивый Markdown-визуал:** Сообщение оптимизировано под особенности парсера TrueConf: важные блоки выделены жирным, используется удобная текстовая гиперссылка на графический интерфейс SIEM, а логи ИБ приходят чистым читаемым текстом.

### 🚀 Быстрый старт и настройка

### 1. Подготовка окружения

Склонируйте репозиторий на целевой Linux-сервер и перейдите в папку проекта: 

bash

git clone <url_вашего_репозитория>
cd trueconf-siem-notifier

Создайте виртуальное окружение и установите зависимости: 

bash

python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
.

### 2. Настройка конфигурационного файла

Создайте файл .env в корневой директории на основе примера: 

bash

cp .env.example .env


Заполните переменные окружения актуальными данными вашей инфраструктуры: 

env

# Конфигурация MaxPatrol SIEM
MPVM_BASE_URL=https://siem-server.corp.local
# Учетные данные системной учетной записи в SIEM задаются внутри mp_vm_variables.py или вашей секретницы

# Конфигурация TrueConf Server
TRUECONF_SERVER_URL=https://trueconf.corp.local
TRUECONF_WS_URL=wss://trueconf.corp.local/bridge/api/client/v1/socket
TRUECONF_USER=bot_username
TRUECONF_PASSWORD=bot_secure_password
TRUECONF_CHAT_ID=c_xxxxxxxxx@each.trueconf.local # GUID целевого канала оповещений

# Системные настройки бота
PAUSE_TIME=60      # Интервал опроса SIEM в секундах
LOG_LEVEL=INFO     # Уровень логирования (DEBUG, INFO, WARNING, ERROR)

### 🛠️ Развертывание в качестве системной службы (systemd)

Для обеспечения непрерывной работы в продакшене и автозапуска при перезагрузке сервера, настройте systemd демон. 

1. Создайте файл конфигурации службы: 

bash
```
sudo nano /etc/systemd/system/siem-trueconf.service
```

2. Вставьте следующее содержимое (скорректируйте пути к проекту): 

```
ini

[Unit]
Description=MaxPatrol SIEM to TrueConf Integration Gateway
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/opt/trueconf-siem-notifier
ExecStart=/opt/trueconf-siem-notifier/venv/bin/python main.py
Restart=always
RestartSec=10

[Service]
# Логи отправляются в системный журнал journald
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

3. Перезапустите менеджер конфигураций, включите автозапуск и запустите службу: 

```
sudo systemctl daemon-reload
sudo systemctl enable siem-trueconf.service
sudo systemctl start siem-trueconf.service
```

### 🔍 Отладка, логирование и разбор ошибок

Бот ведет подробный журнал работы. Проверить статус службы и просмотреть логи в реальном времени можно стандартными командами Linux: 

* **Проверить статус службы:** sudo systemctl status siem-trueconf.service
* **Просмотр логов в реальном времени:** sudo journalctl -u siem-trueconf.service -f -n 100

### Типовые ошибки и способы их решения:

1. **IndentationError / SyntaxError при развертывании в CI/CD:** 

  * *Причина:* Нарушение отступов (микс табов и пробелов) или случайные символы \ переноса строк в файлах tc_messages.py или mp_vm_incidents.py.
  * *Решение:* Убедитесь, что все отступы в блоках if и try/except кратны 4 пробелам.
2. **Сообщения дублируются при перезапуске бота:** 

  * *Причина:* Бот падает до того, как успевает записать новую метку времени в файл last_incident_time.txt, либо у скрипта нет прав на запись в корень своей папки.
  * *Решение:* Проверьте права доступа на папку проекта (chmod/chown). Убедитесь, что блок фиксации времени в main.py выполняется строго после успешной отправки сообщений.
3. **Лог: ❌ TrueConf недоступен. Прерываем отправку текущей пачки...:** 

  * *Причина:* Сервер TrueConf ушел на перезагрузку, упал сетевой маршрут, либо у бота истек/отозван пароль.
  * *Решение:* Бот автоматически перейдет в режим ожидания. Нажмите sudo systemctl status, проверьте доступность хоста TrueConf командой ping или curl. Как только связь восстановится, бот сам продолжит отправку без потери данных.
4. **Лог содержит ошибку 401 для MaxPatrol VM:** 

  * *Причина:* Истек TTL сессионного Bearer-токена SIEM.
  * *Решение:* Штатная ситуация. Главный цикл main.py перехватывает этот код, автоматически вызывает функцию vm_authentificate() для обновления токена и бесшовно продолжает мониторинг.
